# 面试资料导航

这个目录不是简单罗列源码路径，而是把项目真正值得讲清楚的内容重新按“理解项目 -> 准备面试 -> 做代码审查”的顺序组织起来。

适合两类场景：

- 新同学快速理解仓库，不必先从代码细节里摸索。
- 面试前集中梳理设计思路、实现方式、亮点和不足。

## 推荐阅读顺序

### 1. `项目总览.md`

先看整体目标、系统分层、请求链路和数据流，回答“这个项目到底解决什么问题”。

### 2. `核心实现.md`

再看关键模块如何落地，包括：

- MySQL 表结构如何转成 Ontology。
- Demo 实例如何同步进 Neo4j。
- 自然语言如何被规划为查询或动作。
- 知识库检索、ReAct Agent 和 ETL 回流是怎么接起来的。

### 3. `面试指南.md`

最后看适合在面试里直接表达的版本，重点是：

- 如何用 3 分钟讲项目。
- 面试官会追问哪些点。
- 这个项目真正的亮点是什么。
- 哪些不足要坦诚但专业地回答。

### 4. `代码审查.md`

如果你想从工程质量角度评估项目，就看这份审查报告。里面会区分：

- 必须修复的问题。
- 建议优化的问题。
- 已经做得不错的设计。

## 建议用法

如果你是第一次接触这个仓库，建议这样看：

1. 先读 `项目总览.md`。
2. 再对照代码读 `核心实现.md`。
3. 面试前直接过一遍 `面试指南.md`。
4. 如果要做重构或继续扩展，结合 `代码审查.md` 开工。
